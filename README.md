# 100-Sentences-in-English

把一份词表变成一套可以打印、可以背的学习材料：**N 个单词 → M 个句子**，每天一句，配艾宾浩斯回读，边背句子边把单词过完。

仓库里**每个词表是一个独立子项目**，各有自己的主题、故事线、语法进阶、产物和复盘。

## 子项目一览

| 子项目 | 词表 | 句子 | 主题 | 状态 |
|---|---|---|---|---|
| [`420-primary-school/`](420-primary-school/) | 420 个小学必会单词 | 60 句（每句 7 个新词） | 借用哈利·波特的角色名与霍格沃茨场景 | ✅ 完成（第五次修订）：CSV + 32 页 A4 手册 |
| [`1500-KET/`](1500-KET/) | KET 官方词表（Cambridge KET vocabulary list） | 100 句（每句 15 个新词） | 待 `plan/plan.md` 里定 | 🚧 词表准备中，句子未开始 |

**主题由各子项目自定，不强制统一**——这里不是每个词表都用哈利·波特。新项目可以自创故事、借用别的作品，也可以完全不用现成作品；只要在各自的 `plan/` 里把世界观、角色定位定清楚并贯穿全篇即可（借用现成作品时的约束见 [`prompts/2-1500-KET-001.md`](prompts/2-1500-KET-001.md) 第 2 节）。

## 仓库结构

```
prompts/        需求文档，一个子项目一份
                1-420-primary-school-001.md   420 词 → 60 句
                2-1500-KET-001.md             1500 KET 词 → 100 句（第 1 版的改进版，已把教训写成硬条款）
420-primary-school/
1500-KET/
README.md       本文件
```

每个子项目内部遵循同一套目录约定：

```
<项目名>/
├── <项目名>.csv                  词表（英文,音标,词性,中文；单词 id = 数据行号）
├── <项目名>-sentences.csv        学习数据（8 列，见下）
├── <项目名>-sentences.pdf        A4 打印手册（书名 + Howto + 每日卡片）
├── plan/                         执行计划、修订计划、渲染脚本、校验脚本
├── worklog.md                    生成过程与选择逻辑复盘（含踩坑与修订记录）
└── batches/                      分批生成时的中间文件（可选；与最终 CSV 冲突时以 sentences.csv 为准）
```

**文件名一律带项目前缀**：不要用 `sentences.csv` 这类通用名，否则多个词表项目在同一仓库必然撞名（420 项目已因此改过一次名）。数据文件名与 PDF 文件名都按 `<项目名>-sentences.*` 组织。

## 全部子项目共用的规则

1. **覆盖是硬约束，机器可校验**：句子 s 固定覆盖词表 id `(s-1)*K+1` 到 `s*K`（420 = 60×7，KET = 100×15），每个词恰好出现一次，无遗漏、无重复、无表外词。
2. **只许用学过的词**：每句只允许「本句新词 + id 更小的旧词 + 闭类功能词 + plan 里白名单登记的专有名词」；复数、三单、-ing、过去式等变形可用，`new_words` 记原形；**不允许提前使用未学内容词**（顺带：句型也要服从词表顺序，比如 there be 得等 there 成为新词）。
3. **滚动艾宾浩斯复习**：学完一句后在第 1、2、4、7、15、30 天各回读一次；第 d 天（d ≥ 2）的回读任务 = { d-1, d-2, d-4, d-7, d-15, d-30 } 中 ≥ 1 的天，**由脚本统一生成并机器校验，不手写**。回读要求与学新句一样：朗读 → 背诵 → 背写。
4. **先计划再动手**：每个子项目先写 `plan/`，把词分配表、分幕故事线、语法进阶表、白名单、CSV 格式、复习规则一次定死，作为所有批次的统一契约。
5. **分批生成、立即落盘**：建议每批 10 句写入独立文件，中断可续、并发不冲突（420 项目首次生成即靠这个设计在配额中断后无损续跑）。
6. **校验全绿才排版**：结构 / 覆盖 / `new_words` 逐字一致 / 词形真实出现在句中 / 回读规则 / 用词顺序 / 文件格式（UTF-8 带 BOM）——参考 [`420-primary-school/plan/validate.py`](420-primary-school/plan/validate.py)。注意该脚本的常量是 420 专用的（60 行、每句 7 词），新项目要按自己的 K/M 改。
7. **内容自检**（借用现成作品时尤其重要）：角色家庭与身份、称谓词必须带姓氏、学校课程设定、场景自洽、代词指代明确、中英信息对齐——完整清单见 [`420-primary-school/worklog.md`](420-primary-school/worklog.md) 第十节，**新项目开工前先把它当硬约束写进 plan**。
8. **逐步提交**：每个文件生成或重大修改后单独 commit + push。
9. **数量口径唯一**：全书统一词数/句数/幕数，不在不同文档里出现 60/100 混用这类矛盾。

## 新建一个词表项目（例如 PET）

1. `prompts/` 加一份需求文档：词表路径、词数/句数/每句新词数、主题设定、语法进阶、复习规则、CSV 列定义、PDF 排版要求、验收清单。
2. 准备词表 `<项目名>/<项目名>.csv`（列 `英文,音标,词性,中文`，UTF-8 带 BOM）。
3. 写 `plan/plan.md`：词分配表、分幕故事线、语法进阶表、白名单专名、CSV 格式、复习规则；借用现成作品就先过一遍第 7 条的自检清单。
4. 分批生成句子 → 合并为 `<项目名>-sentences.csv` → 跑校验（照 `420-primary-school/plan/validate.py` 改常量）。
5. 渲染 PDF（照 `420-primary-school/plan/render_pdf.py` 改路径、字号、卡片内容），转图抽查首页/Howto/中间页/末页：无乱码、无方框、无大面积空白。
6. 写 `worklog.md` 记录选择逻辑与踩坑，逐文件提交。

## 环境

- Python 3；`weasyprint`（HTML → PDF）、`PyMuPDF`（渲染后转图抽查，环境无 poppler 时用它替代 pdftoppm）
- 字体：中文用 Noto Sans CJK；IPA 音标需要 DejaVu Sans 回退，否则音标显示成方框
- 词表工具（KET 项目）：`requests` + `pdfminer.six`，用于从官方词汇表 PDF 抽取词条
